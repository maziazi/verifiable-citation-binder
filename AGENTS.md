# AGENTS.md — Verifiable Citation Binder (VCB)

Entry point for any agent or human working in this repository. Read this before
touching code. The two sources of truth are `docs/PLAN.md` (what we build, in what
order) and `docs/SPEC.md` (what the system guarantees and why).

## What this project is

A middleware layer that sits between a RAG pipeline and its user. It does two things:

1. **Binds every claim to evidence** — each assertive sentence in a model answer is
   scored against the retrieved chunks it cites, and every score carries a reason code.
2. **Seals the audit trail** — each binding is appended to a hash-chained,
   append-only ledger, so edits and deletions are detectable after the fact.

It is a verification layer. It does not train models and does not improve retrieval.

## Commands

```bash
uv sync                      # install deps (fallback: pip install -e ".[dev]")
uv run vcb demo              # run the end-to-end demo on the bundled corpus
uv run vcb verify <ledger>   # verify a ledger file; exits non-zero if broken
uv run vcb attack <ledger>   # run the 50-case tamper simulation
uv run vcb eval              # run the evaluation harness, write results/
uv run streamlit run app.py  # launch the audit viewer
uv run pytest                # full test suite
uv run pytest -m "not live"  # offline tests only (no API key needed)
uv run ruff check . && uv run ruff format --check .
uv run mypy src/
```

## Working rules

- **Branch + PR.** Never commit to `main`. One PR per capability, per `docs/WORKFLOW.md`.
- **One PR, one capability.** If a PR needs the word "and" to describe it, split it.
- **Tier 1 stays pure.** `src/vcb/core/` must not import from `adjudicate/` or `surface/`,
  and must not perform network I/O. Ledger verification must run with no API key.
- **Tests before merge.** Every PR adds or extends tests. CI must be green.
- **Conventional Commits.** `feat:`, `fix:`, `docs:`, `test:`, `chore:`, `refactor:`.
- **English in the repo.** All `.md`, commit messages, PR titles, and code comments
  are English, regardless of the language used in discussion.

## Hard prohibitions

- **Never commit keys or ledger state.** No `.env`, no `ANTHROPIC_API_KEY`, no
  real `audit_ledger.json` from a user session. Only the fixture ledgers under
  `tests/fixtures/` are tracked, and they are generated by a script.
- **Never call the adjudication model from the hot path of verification.**
  `vcb verify` and `vcb attack` are offline, deterministic, and must stay that way.
  A reviewer with no API key must be able to reproduce every integrity claim.
- **Never return a verdict without `reasons[]`.** A band (GREEN/AMBER/RED/BLACK)
  with an empty reason list is a bug, not a degraded result. Fail loudly instead.
- **Never claim beyond the evidence.** Every quantitative statement in `README.md`,
  `docs/SPEC.md`, or the report carries a verification tag — `[M]` measured,
  `[D]` derived, `[L]` literature, `[A]` assumption, `[F]` future work. An untagged
  number is a defect. See `docs/SPEC.md` §9 for the legend.
- **Never weaken a test to make CI pass.** Fix the code or document the limitation.

## When something is ambiguous

`docs/PLAN.md` wins on scope. `docs/SPEC.md` wins on behavior. If the two conflict,
the conflict itself is a bug — fix the document, then the code.
